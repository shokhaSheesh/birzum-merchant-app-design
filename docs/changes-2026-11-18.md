## 2. Mobile: Fortuna / Vodiy app (`fortuna-biznes-mobile`)

- **M3. Sign with MyID.** After «Pul qaysi kartaga tushsin?» → «Davom etish», open the MyID face screen instead of the SMS code. On a match, the payout starts. On a mismatch: «Yuz tasdiqlanmadi» with «Qayta urinish» / «Keyinroq», no retry limit. Texts change from «SMS-kod bilan» to «MyID orqali», and the button to «Imzolashga oʻtish». *Waits on backend (see 4).*
- **M4. Income on the ariza.** New required field «Oylik daromad» under «Ish joyi», filled in from the profile and editable. A change applies to this ariza only; the profile keeps its own value. *Backend: add the field to the request.*
- **M5.** Text `details.card.hint`: «Daromadni baholash uchun.» / «Для оценки дохода.»
- **M6. Own card only.** After the card's SMS code, if the backend says the card's owner is someone else: «Karta sizning nomingizda emas» + «Boshqa karta qoʻshish». The card is not added. *Backend: an error code from `/client/cards/confirm`.*
- **M7. Balance.** In Profil → «Kartalarim», show the balance under the card name. `GET /client/cards` already returns `balance_tiyin` and `balance_at`. Only on that page, not in the card pickers.
- **M8. Code before paying.** After «Oʻzim bajaryapman», add a step «Toʻlovni tasdiqlash»: the code field, «Kodni qayta yuborish» with a timer, «{sum} toʻlash». Automatic monthly debits don't ask for a code. *Backend: a confirm step (see 4).*
- **M9.** Remove «Fiskal chekni koʻrish» from «Toʻlov tafsilotlari».

## 3. Admin front (`birzum_react_admin`)

- **A3.** Add status `received` «Mijoz qabul qildi» / «Клиент получил» (blue badge) between «Shartnoma yaratildi» and «Shartnoma tasdiqlandi», plus the status filter and the «Tarix» line «Klient: <name>». It counts as open.
- **A4.** Ariza → «Olish usuli»: under «Manzil», show «Uy», «Xonadon», «Podyezd», «Qavat», «Moʻljal / kuryerga izoh» (only the filled ones).
- **A5.** Product page: a «Sharhlar» block with the average, stars, «N ta sharh» and the 3 latest reviews with replies. «Hammasi» opens Sharhlar filtered to this product. ✅ `GET /admin/reviews` already takes `product_id`.
- **A6.** Microloan ariza: in «Tarix», «Imzolandi» reads «MyID orqali yuz tekshiruvi bilan imzolandi». The «Mijoz aytgan» block becomes «Arizada koʻrsatilgan» with the note «Shu ariza uchun. Profildagi daromad oʻzgarmaydi.». `monthly_income_tiyin` is on `AdminApplication`; `/admin/apps/{app}/applications` exists but isn't wired yet.
- **A7.** Microloan client: a separate «Kartalar» block. Each card has its balance and «Karta egasi JSHSHIR boʻyicha mos (Atmos)». *Backend: cards in the admin client profile.*
- **A8.** Remove the «Fiskal chek» button and window. The method label becomes «Ilovada toʻladi (Atmos SMS kod)».
- **A9.** Yordam chati in 2 columns (no client panel):
  - The header has the photo, name (opens the client page), topic and phone.
  - 🔍 «Chatdan qidirish»: matches, «2 / 5», ↑ ↓, Esc.
  - «Operatorga oʻtkazish» dropdown, which also works for a chat in the queue. ✅ `POST …/chats/{id}/assign`.
  - ✓✓ on the operator's messages. *Backend: a read mark on messages.*
- **A10.** Merchant page:
  - A dashboard with its own period: Savdo hajmi, Arizalar with «Qabul qilingan %», Reyting, Salbiy sharhlar, each with its change against the previous period.
  - A sales line chart.
  - Tabs: Filiallar, Xodimlar, Mahsulotlar, Arizalar, Sharhlar.
  - Data stays read-only except «Koʻrinish».
- **A11.** Client → «Limit tarixi»: one row per FlexSoft scoring or manual change, plus a line chart when there are 2 or more changes.
- **A12.** Microloan client: chart «Soʻralgan va taklif qilingan summalar», one point per ariza. `amount_tiyin` and `offered_amount_tiyin` are on `AdminApplication`.
- **A13.** Faoliyat jurnali for each workspace:
  - Tab «Ilova va integratsiyalar»: steps of sign-in, MyID, cards, scoring, arizalar, payments and support, with service, result, error code, and request / response JSON.
  - Tab «Admin amallari»: the existing log, scoped to that workspace.
  - New role page «Mikroqarz faoliyat jurnali».
- **A14.** New page «Qarzdorlar» (`/debts`, `/debts/:id`):
  - One card per late nasiya, 9 statuses (Yangi qarz and Yopildi are set by the system).
  - Kanban (main view) and a table.
  - A call form with 8 results, next call, operator, status history.
  - A new «Hisobot» tab in «Toʻlovlar» (promises and operators).
  - The «Qarzdorlar» tab is removed from «Toʻlovlar».
  - Updated 19.11: see [changes-2026-11-19.md](changes-2026-11-19.md) (A15, A16).
  - New role page «Qarzdorlar».

## 4. Backend: what is needed

| For | Need | Today in swagger |
|---|---|---|
| M3 | Sign a contract with MyID: start a MyID session for the offer, then a call that signs it after the face matches (our MyID call, not through FlexSoft) | No endpoint. Sign-in uses `/auth/client/myid/session` + `/auth/client/face`; signing needs the same for an ariza |
| M4 | `monthly_income_tiyin` in `POST /client/applications`, sent to FlexSoft with the ariza; the profile value is not changed | The response (`ClientApplication`) has it; the request (`ClientApplicationRequest`) doesn't |
| M6, A7 | Atmos returns the card owner's PINFL after the code; compare it with the client's and refuse with an error code (e.g. `card_not_owner`) | `POST /client/cards/confirm` exists, no such check or code documented |
| M8 | In-app payment in two steps: create (Atmos sends the code) → confirm with the code; plus resend | `POST /client/loans/{id}/payments` takes the payment at once, no confirm step |
| A3 | Ariza status `received`, set by the client app's «Mahsulotni qabul qildim» | Not in swagger; BNPL ariza endpoints for the admin aren't there yet (mocked) |
| A4 | Delivery address parts (house, apartment, entrance, floor, note) in the admin ariza | Admin ariza endpoints mocked |
| A7 | Cards (masked number, balance, owner-matched) in the admin client profile | `AdminClientProfile` has no cards |
| A9 | A read mark on chat messages (`read_at` or similar) for ✓✓ | `ChatMessage` has no read field |
| A10 | Merchant stats for a period (sales, arizalar decided / accepted, negative reviews, sales series), plus the merchant's products, arizalar and reviews lists | `Merchant` has only `sales_this_month_tiyin`, `rating`, counts |
| A11 | `GET /admin/clients/{id}/limit-history` (each scoring and manual change) | Mocked in the admin, not in swagger |
| A13 | App and integration events per workspace: list with filters, and one event with request / response | No endpoint |
| A14 | Debt cases per nasiya: list, one case, status change with reason, call record (8 results, client answer, comment, next call, status after), next call, operator, reports (promises by month, operators) | Only mocked `/admin/collections/*`; nothing in swagger |
